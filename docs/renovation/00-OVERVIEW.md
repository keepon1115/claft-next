## 1. 改造の目的

主役は**子ども(スクール生)が家で自主的に使う**体験。同じアカウントで保護者も閲覧する(非認知能力レポート等)。

## 4. 共通実装ルール(全フェーズ厳守)

1. **ナビはデータ駆動**: `components/common/navConfig.ts`(フェーズ1で作成)を唯一の正とする。Sidebarにリンクをハードコードしない
2. **既存パターン踏襲**: 各ページは `HamburgerMenu` + `Sidebar` + `'use client'` の既存構成に従う
3. **認証**: `useAuth()` を使用。閲覧は原則ログイン不要、個人データ(非認知PDF等)のみ認証必須
4. **コンテンツはコード管理**: 動画リスト・リンク集・ゲーム一覧・偉人カタログは `data/` 配下のTSファイルで管理(管理画面は作らない — オーナーの運用方針)。個人データ(非認知PDF・気質・強み)はSupabaseダッシュボードから管理者が直接入力。例外は手紙管理のみ(11-B、返信作業が日常運用のため専用ページを作る)
5. **モバイルファースト**: 375px幅で崩れないこと。iframe系は `100dvh` 基準
6. **スタイリング**: Tailwind。グループテーマは各ページ内で完結させ、globals.cssを汚さない
7. **削除より温存**: 既存ルートは物理削除せずリダイレクト(`next.config.ts` の redirects か page内redirect)
8. **PWA注意**: 大きな静的アセット(Godot wasm等)は本体にバンドルしない。外部ホスティング+iframe
9. **各フェーズ完了時**: `npm run build` が通ること。既存ページ(especially `/quest`, `/admin`)のデグレがないこと

### Godot側作業の分担(10〜12共通)

Godotプロジェクトは `yononaka-map/`(同一リポジトリ)。`.gd` `.tscn` `.cfg` `.json` はテキストなのでAIが編集できるが、
**動作確認(F5)とWeb書き出し(Project → Export)はオーナーがGodotエディタで行う**。AIはGodotを実行できない。
