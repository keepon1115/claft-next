# フェーズ5: メンバーを知る(村の広場・メタライフ風) — 目玉機能

前提: `00-OVERVIEW.md`、フェーズ1完了。

## 目的

「アバターが空間にいて、お互いのプロフィール・作品・成長が見え合う」メタライフ的な広場を作る。
既存の冒険者一覧(`/yononaka`内)とアントレプレナーページを統合・進化させる。

## 設計判断(確定済み)

- **大人に出会う=Godotマップ / メンバー同士=このページ**と役割分離
- 理由: 更新頻度の違い(メンバーは週次で動く)、Godot Web書き出しの肥大化回避、既存資産の即戦力化
- 将来、このページのデータ(アバター・作品)をGodotマップの「CLAFT村ゾーン」に流用する構想。データ構造はその前提で設計(Supabase共有)

## デザイントーン: 村の広場・メタライフ風

- 芝生 `#7ec850` / 空色 `#aee3f5`。上1/3が空、下2/3が芝生の広場
- ドット絵/ゲーム風。家・木・ベンチなどの背景小物はCSS/絵文字/簡易SVGでよい(画像アセット不要で始める)
- アバターは既存プロフィールのアバター画像を丸枠+ニックネーム札で表示。ふわふわ浮遊アニメ(`framer-motion`は導入済み)

## 既存資産(必ず流用)

- `hooks/useAdventurerList.ts` — 冒険者(メンバー)一覧取得
- `components/yononaka/UserProfileModal.tsx` — プロフィールモーダル
- `app/entrepreneur/page.tsx` — 統合するコンテンツ
- `app/yononaka/page.tsx` — 冒険者一覧セクションの移設元

## 対象ファイル

- 新規: `app/members/page.tsx`
- 新規: `components/members/Plaza.tsx`(広場)、`components/members/MemberAvatar.tsx`
- 改修: `next.config.ts` — `/yononaka` と `/entrepreneur` を `/members` へリダイレクト
- 改修(移設のみ): UserProfileModal を `components/members/` へ移動 or そのままimport(そのままで可)

## 実装内容

### 1. 広場(Plaza)

- `useAdventurerList` で全メンバー取得
- 各メンバーをアバターとして広場に配置。**位置はuser_idのハッシュから決定論的に算出**(毎回同じ場所に住む=「あの子の定位置」感)。重なりは格子+ジッターで回避
  - このハッシュ配置アルゴリズムはフェーズ9でGodotマップ側と共有する(「両世界で同じ定位置」)。単純で移植しやすい実装にすること
  - アバター見た目: フェーズ9aで`member_avatars`のドット絵スプライトに置き換わる。本フェーズでは既存プロフィール画像でよいが、`MemberAvatar`は見た目ソースを差し替えられる構造にしておく(`09-avatar-sync.md`参照)
- クリック/タップ → `UserProfileModal` を開く(プロフィール・作品・成長が見える)
- 人数が多い場合は広場を横スクロール可能に(モバイル: ドラッグスクロール)
- 自分のアバターには「きみ」バッジ+目立つリング

### 2. モーダル拡張(見え合いの中身)

UserProfileModal に(既存表示に加えて)タブまたはセクション追加:
- **プロフィール**: 既存表示
- **成長**: クエスト進捗(`user_stats`/questStoreの統計から取れる範囲。バッジ表示はホームのbadgeロジック流用)
- **作品**: 当面は将来枠。「作品はまだ準備中」空状態でよい(ひらめきポスト投稿の一覧を出せるなら出す — 実装時にテーブルを確認して判断)

### 3. アントレプレナー統合

- 広場の下に「アントレプレナーのひろば」セクションを設け、`/entrepreneur` の中身を移植
- 移植完了後にリダイレクト有効化

## 注意

- 個人情報: 表示するのはニックネーム・アバター・公開プロフィール項目のみ。本名やメールは絶対に出さない(既存モーダルの表示項目に従う)
- 未ログインでも広場は見られる(モーダルの個人詳細は既存の公開範囲に従う)
- パフォーマンス: アバター画像は `OptimizedImage`/`next/image` 使用。50人程度で60fpsを保つ(アニメはtransformのみ)
