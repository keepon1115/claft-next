# 発注書：ロボットコース振り返り機能「ロボクエスト」（仮称）v1

CLAFTアプリ（claft-next）への機能追加。下記の実装を最後までやり切ってください。
調査報告で止まることは不合格です。コードの変更・動作確認まで済ませ、検収できる状態で引き渡してください。

---

## 0. 背景（読むだけでよい）

エジソンアカデミー（ロボットプログラミング教室、小3〜）では、授業の最後に振り返りをGoogleフォームで行ってきた。構成は「知識クイズ3問（3択・テキスト参照可）＋正解が一つでない問い（自由記述）＋感想」。これをCLAFTアプリ内のゲーム形式UIに置き換える。

- 利用場面：授業の最後、教室のPCで、5〜10分
- 対象：小学3年生〜。全24テーマ×2年間（月2回ペース、カリキュラムはレベル1〜8の階段構造）
- 設計思想：**クイズパートはにぎやかなゲーム（昼の声）、問いパートは画面のトーンを落とした静かなモード（夕方の声）**。1画面遷移の中で明確にモードが切り替わること
- ゲームの参照イメージ：Duolingo（1問1画面、即時フィードバック、プログレスバー、正解演出）

## 1. 納品物

以下がすべて動く状態になれば納品。

### A. 生徒向け画面（`app/robo/` 配下を新設）

1. **ステージマップ** `/robo`
   - 24テーマをレベル1〜8の階段構造で表示（seedは1テーマのみだが、マップはテーマデータの件数に応じて動的に描画されること）
   - クリア済みテーマにはスタンプ/バッジ表示。未公開テーマはロック表示
2. **クイズパート** `/robo/[themeId]`（昼の声・にぎやか）
   - 1問1画面、3択、回答すると即時に正誤フィードバック（正解時は既存依存のcanvas-confetti等で演出。アニメーションはFramer Motion。**新規依存パッケージの追加は禁止**）
   - 上部にプログレスバー。3問連続正解で追加演出
   - 不正解でも先に進める（テキスト参照OKの文化なので、ペナルティ・減点・ランキングは作らない）
   - 設問には任意で画像を1枚添付できること（例：lv1-1のQ2は工具の写真を見せて名前を問う）
3. **問いパート** 同フロー内（夕方の声・静か）
   - クイズ終了後、背景色・トーンが落ち着いた暖色系に切り替わる演出を挟んでから「正解が一つでない問い」を表示
   - 自由記述で回答を入力・送信
   - **送信後にのみ**、同テーマに答えた他の生徒の回答が積み上がったウォールが見える（新しい順。ニックネーム表示）
4. **感想入力 → 完了画面**
   - 感想（自由記述）を送信すると、テーマクリアのスタンプ獲得演出 → ステージマップへ戻る
5. 同一テーマの再挑戦は可とする。ただし問い・感想の回答は上書きではなく最新のものを有効とする（履歴は保持）

### B. 管理者向け（既存の `app/admin/` のパターンに合わせて追加）

1. **テーマ・設問管理**：テーマのCRUD、設問（3択・正解・解説文・画像URL・参照ページ）のCRUD、問いテキストと「事例解説」（Markdown）の編集、テーマの公開/非公開切り替え
2. **回答閲覧**：テーマ別に全生徒の回答一覧。問いの回答を個別に非表示にできる（非表示はウォールから消えるが、データは残る）
3. **A4印刷ビュー**：生徒×テーマ単位で1枚。内容＝①クイズ結果（設問・選んだ答え・正誤）②本人の問いへの回答 ③クラスの回答からの抜粋（表示中のもの最大5件程度）④事例解説（Markdown描画）。`@media print` でブラウザ印刷がそのままA4に収まること

### C. データベース（`supabase/migrations/` に追加）

推奨テーブル構成（既存の命名規則・RLS運用を必ず先に読み、それに合わせて調整してよい。構造の意図は変えないこと）：

- `robo_themes`：テーマ（レベル番号、テーマ番号、タイトル、問いテキスト、事例解説Markdown、公開フラグ、表示順）
- `robo_questions`：設問（テーマID、本文、選択肢3つ、正解インデックス、画像URL nullable、参照ページ表記 nullable、表示順）
- `robo_enrollments`：ロボットコース在籍（user_id）。**既存のusersテーブルやCLAFTコースの識別方法を先に調査し、既存機構で表現できるならそれを使う。できない場合のみこのテーブルを作る**
- `robo_quiz_answers`：クイズ回答ログ（user_id、question_id、選択、正誤、回答日時）
- `robo_open_answers`：問いへの回答（user_id、theme_id、本文、表示フラグ、作成日時）
- `robo_feedbacks`：感想（user_id、theme_id、本文、作成日時）
- `robo_theme_clears`：クリア記録（user_id、theme_id、クリア日時）

RLS必須。生徒は自分の回答の読み書き＋表示フラグONの他者open_answersの読み取りのみ。管理者はadmin判定の既存機構に従う。

### D. Seedデータ（テーマ1件分）

**lv1-1「信号機をつくろう」**

- Q1：センサーやモーターをスタディーノにつないだら、プログラミングをする前に、パソコンに「どこになにをつないだか」を教えてあげなければいけません。それはどうやって教えてあげますか？（P.13）
  - プログラミング画面にむかってさけぶ。／プログラミング画面の「編集（へんしゅう）」→「入出力設定（にゅうしゅつりょくせってい）」【正解】／プログラミング画面でマウスを10回クリックする。
- Q2：ブロックがかたすぎて外れないときに使うこれのなまえは？（P.34）※画像あり（工具の写真。画像アセットは発注者が後日差し込むため、画像URLはプレースホルダでよい）
  - ブロックはさみ／チョキチョキくん／ブロックリムーバー【正解】
- Q3：ロボットプログラミングは、上から順番に実行されていきます。この処理のことをなんというでしょう？（P.17）
  - 順次処理（じゅんじしょり）【正解】／ごみ処理（ごみしょり）／背の順処理（せのじゅんしょり）
- 問い：もし、信号がなかったら？あるいは信号を守らなかったら？どんなことが起こる？
- 事例解説（Markdown）：「信号がない場合に、交通事故や渋滞が起こりますよね。信号があることによって事故や渋滞がなくなれば、経済的な効果があるだけでなく、環境を守ることにもつながります。また、救急車やパトカーなど、一刻も早く目的地に到着しなければならない緊急車両の助けにもなると考えています。」

## 2. 作業場所

- 新設：`app/robo/`、`components/robo/`、`app/admin/` 配下のロボ管理ページ、`supabase/migrations/`、必要なら `types/`・`lib/api/`・`stores/`
- 着手前に必読：既存の認証（`hooks/useAuth`・`stores/authStore`）、admin実装パターン、Supabaseクライアント（`lib/supabase/`）、既存migrationsの規約

## 3. 立入禁止

- 既存機能（quest、yononaka、minecraft-sdgs、twilight 等）のコード・スキーマ・挙動を変更しない。yononakaはUIパターンの参考にしてよいが、データ・コンポーネントの共有はしない
- 新規npmパッケージの追加禁止（Framer Motion、canvas-confetti、React Hook Form、Zod 等の既存依存で賄う）
- 認証の仕組みを新設しない。既存のSupabase Authに乗る
- 子どもの個人情報：新テーブルにフルネーム・学校名等を持たない。表示は既存のニックネーム/プロフィール機構を使う

## 4. UI・トーン指針

- 既存アプリのデザインシステムに従う。クイズパート＝明るくにぎやか、問いパート＝落ち着いた暖色（夕方）トーンへの明示的なモード切替を必ず入れる
- 問いパートに点数・ランキング・競争要素を一切入れない。「いいね」等のリアクションもv1では入れない
- 全画面、小3が読める表記（漢字にはUI文言上の配慮、フォントサイズ大きめ）。PC前提だがタブレットでも崩れないこと

## 5. 合格ライン（機械的に判定できる条件）

1. `npm run build` が通り、`npm run lint` にロボ機能起因のエラーがない
2. 生徒アカウントで：ステージマップ→lv1-1→3問回答→問い回答→他者回答ウォール表示→感想→スタンプ獲得→マップに反映、が一連で完走できる
3. 問いの回答は自分が送信するまで他者分が見えない（未送信状態でウォールが見えたら不合格）
4. 管理者で：設問の編集、回答一覧の閲覧、任意の回答の非表示化（ウォールから消える）、印刷ビューのA4出力（印刷プレビューで1枚に収まる）ができる
5. RLS：生徒アカウントから他生徒のquiz_answers・feedbacksがAPIレベルで取得できない
6. 既存ページ（/quest、/yononaka、/admin既存機能）が回帰なく表示される

## 6. 検収方法

- ローカルで `npm run dev` を起動し、生徒ロール・管理者ロールの2アカウントで合格ライン2〜4を手動確認
- Supabaseダッシュボードまたはanon keyでの直接クエリで合格ライン5を確認
- `npm run build && npm run lint` の実行結果を報告に添付

## 7. 報告様式

- 変更・追加したファイルの一覧
- 施工内容の要約（コード全文は不要）
- 検収の実施結果（合格ライン1〜6それぞれ）
- 懸念（なければ「なし」と書く）

## 8. v1でやらないこと（積み残しとして明記）

- テーマの一括CSVインポート（2テーマ目以降が増えてから検討）
